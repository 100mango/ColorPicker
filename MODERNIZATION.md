# TouchColor iOS modernization

## Scope and preservation

The published 1.0 app is identified by App Store ID **859727780** and bundle ID **com.mango.touchColor**. Repository commit `c21792c` immediately predates the `de4a30f` redesign. It confirms the shipping-era features and persistence contract:

- Photo library selection and camera photo capture, tap/drag color sampling, pinch zoom
- Live camera center-pixel sampling with numeric RGB/hex readout
- Ordered, duplicate-preserving saved colors and individual deletion
- `NSUserDefaults` key `colorArray` storing lowercase `#rrggbb` strings

This branch continues from `df48f02` but does not assume its unfinished 2.0 interface is release-ready. It keeps those behaviors with safe-area, Dynamic Type, VoiceOver-labeled UIKit controls; PhotosUI's system picker requires no broad photo-library authorization. Scene lifecycle and a system launch screen replace the old app-only lifecycle/XIB launch path. The three feature paths remain available. The app retains its bundle identity, historical iPhone-only device family (`TARGETED_DEVICE_FAMILY=1`) and published droplet icon identity. Adaptive layout improvements remain, but this compatibility release does not add native iPad support. See recovered artwork provenance below.

GPUImage 0.1.7 and the unused Masonry dependency are no longer linked. Live sampling uses AVFoundation 32BGRA frames, actual row stride and center coordinates, serial session work off the main thread, permission gating, interruption handling and a bounded 10 Hz UI update. Automatic wide-color configuration is disabled before explicitly requesting sRGB. Photo sampling renders exactly one displayed-image pixel into explicit sRGB, applies UIImage orientation and composites transparency on white. Camera exposure/white balance are device-dependent: this is a color picker, not a calibrated colorimeter.

Legacy history is read without rewriting. On a subsequent user edit, malformed entries are skipped and the untouched original is preserved under `colorArrayRecoveryBackup`. Valid order and duplicates remain. Saves are disabled until a valid sample exists. English and Simplified Chinese strings are included. No tracking, collection SDK, analytics or application-server data transmission is linked. The accessible Privacy Policy navigation entry opens the verified [policy page](https://100mango.github.io/app-privacy/) in a native-close, fixed-document WebKit view with JavaScript disabled and nonpersistent storage. It performs the ordinary website request, restricts navigation to the approved document, and opens only the approved contact mailto after an explicit user tap. Offline/server errors show a native Retry control. The privacy manifest declares app-only UserDefaults access (CA92.1).

## Build and test

App deployment target: iOS 15.0. Xcode 27 XCTest targets use iOS 17.0 because its test frameworks require iOS 17 or newer; that does not change the app deployment floor. Intended validation toolchain: **stable Xcode 27.0 / iOS 27.0**, never beta. The checked-in Xcode project is reproducibly generated by `python3 scripts/generate_project.py`. Open `TouchColor.xcodeproj` or `TouchColor.xcworkspace`; CocoaPods is not needed. The original storyboard/XIB/helper sources remain only as historical design references and are excluded from the target.

The single-job Actions workflow runs on the fixed modernization branch with exact source/workflow SHA assertions before and after checks, nonpersisted checkout credentials, and an observed framework inventory. It records `sw_vers`, Xcode/SDK versions and simulator inventory, checks project reproducibility, builds unsigned Release for physical-device architecture, and runs unit/UI XCTest suites in separately visible, time-bounded steps on a compact iPhone 17e and a large iPhone 18 Pro Max serially. It does not cache builds, store artifacts, sign, archive/upload, merge, or submit to App Store Connect. Tests cover legacy/malformed/empty history, save/reopen/delete, byte/hex validation, asymmetric pixel fixtures for all eight orientations and scales, transparent pixels, letterbox rejection, permission states, BGRA center sampling with padded row stride and unsupported formats, largest accessibility text reachability, privacy-policy repeated open/native-close, background return, deterministic offline Retry, and URL/contact allowlist validation, real system photo-picker select/cancel, no-camera behavior, background/foreground, rotation, and save/relaunch. Debug-only fixture injection is excluded from Release. Two bounded synthetic-only JPEG screenshots are logged for visual review; no artifact upload is used.

## Release gates (not implied by simulator CI)

- Physical iPhone camera sampling: verify center alignment and RGB under portrait/landscape, permission allow/deny/restricted, camera busy/interruption, background/foreground, long sessions, hot/cold launch and Settings revocation
- VoiceOver navigation, largest accessibility text sizes, very large/iCloud/HEIC/wide-gamut photos, memory/performance and visual review
- Earliest supported iOS 15 run on a suitable archived test environment/device (the stable modern runner may not include it)
- Existing-install upgrade test from the actually published binary; historical source is evidence, not a signed installed baseline
- Owner reviews intended UI refresh, deployment-floor change, App Store version/build availability, privacy questionnaire, age rating, screenshots/support URLs; current `2.0`/`20001` values are proposed only
- Confirm developer-team access, signing/provisioning and App Store Connect record with the owner. No credentials are embedded and no submission is authorized by a green compile alone

Official references: [PHPicker](https://developer.apple.com/documentation/photosui/phpickerviewcontroller), [scene lifecycle](https://developer.apple.com/documentation/uikit/transitioning-to-the-uikit-scene-based-life-cycle), [privacy manifests](https://developer.apple.com/documentation/technotes/tn3183-adding-required-reason-api-entries-to-your-privacy-manifest), [runner toolchains](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md).

It is not represented as the original designer source. Original downloaded PNG SHA-256: `f76d9649746cafe4d93228322fe4b8eb298b05af39cf0b1638d445bb4c534231`. [Apple CDN source](https://is1-ssl.mzstatic.com/image/thumb/Purple/v4/99/90/ad/9990ad96-b4cc-7c2a-9daf-92b94f399df6/mzl.qymjxyuo.png/1024x1024bb.png). The iPhone/App Store icon slots and retained unused iPad slots are generated from that same artwork by ordinary resizing. No identity replacement or generated artwork was used. The released 1.0 App Store record is verified; the currently proposed build number remains subject to checking before upload.

## Store screenshots

The approved iPhone screenshots were captured from Release using the real system photo picker and UI save flow on iPhone 18 Pro Max, in Simplified Chinese. The later device-family correction changes no visible app source or iPhone appearance. Earlier iPad captures are test-only evidence and are excluded from the App Store screenshot package; they do not advertise native iPad support.

A real large-iPhone CI failure showed the system Safari Done control could leave its view presented. The fixed-document viewer keeps Close in the app-owned navigation bar, and the UI tests retain the return-to-home and hittability assertions.
