# TouchColor iOS modernization

## Scope and preservation

The published 1.0 app is identified by App Store ID **859727780** and bundle ID **com.mango.touchColor**. Repository commit `c21792c` immediately predates the `de4a30f` redesign. It confirms the shipping-era features and persistence contract:

- Photo library selection and camera photo capture, tap/drag color sampling, pinch zoom
- Live camera center-pixel sampling with numeric RGB/hex readout
- Ordered, duplicate-preserving saved colors and individual deletion
- `NSUserDefaults` key `colorArray` storing lowercase `#rrggbb` strings

This branch continues from `df48f02` but does not assume its unfinished 2.0 interface is release-ready. It keeps those behaviors with safe-area, Dynamic Type, VoiceOver-labeled UIKit controls; PhotosUI's system picker requires no broad photo-library authorization. Scene lifecycle and a system launch screen replace the old app-only lifecycle/XIB launch path. The three feature paths remain available. The frozen iPhone checkpoint `565b769` retains the historical iPhone-only scope. The subsequent native iPad branch expands `TARGETED_DEVICE_FAMILY` to `1,2` with a genuine UIKit palette/canvas workspace, while retaining the bundle and published droplet icon identity. See recovered artwork provenance below.

GPUImage 0.1.7 and the unused Masonry dependency are no longer linked. Live sampling uses AVFoundation 32BGRA frames, actual row stride and center coordinates, serial session work off the main thread, permission gating, interruption handling and a bounded 10 Hz UI update. Automatic wide-color configuration is disabled before explicitly requesting sRGB. Photo sampling renders exactly one displayed-image pixel into explicit sRGB, applies UIImage orientation and composites transparency on white. Camera exposure/white balance are device-dependent: this is a color picker, not a calibrated colorimeter.

Legacy history is read without rewriting. On a subsequent user edit, malformed entries are skipped and the untouched original is preserved under `colorArrayRecoveryBackup`. Valid order and duplicates remain. Saves are disabled until a valid sample exists. English and Simplified Chinese strings are included. No tracking, collection SDK, analytics or application-server data transmission is linked. The accessible Privacy Policy navigation entry opens the verified [policy page](https://100mango.github.io/app-privacy/) in a native-close, fixed-document WebKit view with JavaScript disabled and nonpersistent storage. It performs the ordinary website request, restricts navigation to the approved document, and opens only the approved contact mailto after an explicit user tap. Offline/server errors show a native Retry control. The privacy manifest declares app-only UserDefaults access (CA92.1).

## Build and test

App deployment target: iOS 15.0. The checked-in XCTest targets currently use iOS 17.0; that does not change the app deployment floor. A compatible earlier-runtime test configuration and availability guards are required before running the same harness below iOS 17. Intended validation toolchain: **stable Xcode 27.0 / iOS 27.0**, never beta. The checked-in Xcode project is reproducibly generated by `python3 scripts/generate_project.py`. Open `TouchColor.xcodeproj` or `TouchColor.xcworkspace`; CocoaPods is not needed. The original storyboard/XIB/helper sources remain only as historical design references and are excluded from the target.

The Actions matrix runs four fresh standard hosts serially (`max-parallel: 1`) on the fixed native-iPad branch with exact source/workflow SHA assertions before and after checks, nonpersisted checkout credentials, and an observed framework inventory. It records `sw_vers`, Xcode/SDK versions and simulator inventory, checks project reproducibility, builds unsigned Release for physical-device architecture, and runs unit/UI XCTest suites in separately visible, time-bounded steps on an explicitly discovered/created iPhone SE (3rd generation), 375×667 points, iPhone 18 Pro Max, native 13-inch iPad Pro and iPad mini (A17 Pro). Each job independently rebuilds the same exact source. Boot readiness and app installation/launch are gating checks; broad launchctl and destination inventories are timestamped, short-bounded diagnostics. Final tracked-source integrity runs even when tests fail, without converting a failing test result into a pass. It does not cache builds, store artifacts, sign, archive/upload, merge, or submit to App Store Connect. Tests cover legacy/malformed/empty history, save/reopen/delete, byte/hex validation, asymmetric pixel fixtures for all eight orientations and scales, transparent pixels, letterbox rejection, permission states, BGRA center sampling with padded row stride and unsupported formats, largest accessibility text reachability, privacy-policy repeated open/native-close, background return, deterministic offline Retry, and URL/contact allowlist validation, real system photo-picker select/cancel, no-camera behavior, background/foreground, rotation, and save/relaunch. Debug-only fixture injection is excluded from Release. Two bounded synthetic-only JPEG screenshots are logged for visual review; no artifact upload is used.

## Deeper compatibility repairs

- Tap/drag and Sample Center share the same point-sampling path. The selected location is stored in image-normalized coordinates, so the marker remains on the selected pixel after layout, rotation and letterboxing. A three-column/two-row asymmetric RGB fixture exercises distinct color regions, pan/zoom math, and marker/readout agreement.
- The shipped non-pinch zoom control is restored as an accessible logarithmic slider spanning the existing 1–100× range. Photo controls and privacy error recovery scroll in short windows and at large text sizes. Dark-mode synthetic UI coverage is included.
- Live frames carry a capture generation. Pause, interruption and runtime failure immediately invalidate the generation and savable sample, including before queued main-thread delivery. Restart is compare-and-start guarded. Controlled ordering tests exercise actual display/interruption methods without pretending to test camera hardware.
- Existing HTTP failure and WebKit process-termination handlers now have direct tests. Offline Retry waits for the approved policy document body, and largest-text landscape checks verify Retry/Close reachability. Historical `colorArrayRecoveryBackup` remains intact after deletion/relaunch.
- Photo fidelity remains full resolution. Sampling allocates only a 1×1 destination; the controller and image view retain the same source UIImage rather than separate explicit full-image copies. Full source decoding/retention can still be large and requires physical memory/performance measurement; no silent downsampling or unsupported memory guarantee is introduced.

Store screenshots captured before this section are a historical baseline: the restored zoom control changes the photo screen and requires fresh release screenshots after the final tests pass.

The first iOS27 SE3 pass exposed a real largest-text home constraint: the fixed source-button stack could leave the history viewport shorter than its RGB label. Source actions now scroll within at most half the safe height, preserving a readable history region. The matching UI test scrolls each source action into view and retains full RGB-label containment assertions. The largest-text policy test uses production navigation without the unrelated Debug fixture button.

A Debug-only camera-availability probe exercises the real AVCaptureDevice permission API and OS Allow → foreground return → reset → Deny dialogs on simulator, then stops before camera presentation. This is real TCC behavior through the permission branch, not a claim that a simulator has a camera or that physical capture is verified. ## Native iPad workspace

The iPad window has independent palette and canvas navigation, with system split-column adaptation. A compact palette can return to the current canvas without discarding its selected photo or pixel. The original ordered palette refreshes after saves while remaining visible. Empty-state text and large-text controls scroll; source titles retain their full intrinsic height. Photo controls prefer a balanced canvas but can grow enough to expose one whole readout or action in a short window, while reserving at least 44 points for the canvas.

Photo selection uses an anchored system PHPicker popover. When the palette is hidden or its button is scrolled away, the source toolbar provides the anchor. Loading is visible on the current canvas as well as the palette. A source flow explicitly invalidates live-camera generations even when a partial popover leaves the canvas visible; cancellation resumes only in a visible, active scene. iOS 17 and later use AVFoundation's device rotation coordinator for preview rotation; iOS 15–16 retain the scene-orientation fallback. Center sampling remains invariant under the centered crop and rotation, but this is not a claim of camera calibration or tested external-camera behavior.

Hardware-keyboard actions include Command-O (photo), Shift-Command-O (camera), Command-L (live), Command-1 (palette), Command-S (save), Space (center sample), +/−/Command-0 (zoom/reset), and arrows (one source-image pixel). A pointer crosshair marks the sampling surface and source/save buttons use native pointer interaction. The iPad suite exercises actual system photo selection, palette refresh, cancellation, keyboard import/zoom/save, rotation, scene lifecycle and privacy return. Direct UIKit tests cover command pixel movement, pointer construction, generation invalidation and legacy order. Physical pointer hardware remains separate validation.

Primary CI uses four fresh standard Xcode 27.0/27A266a jobs with at most one running concurrently, independent Release builds/static analysis, and iOS 27.0 tests on SE3, iPhone 18 Pro Max, native 13-inch iPad Pro and iPad mini (A17 Pro). Additional real UIKit view hierarchies are constrained to 320×568, 568×320 and split-window widths of 320/507/694/1024 points at the largest Dynamic Type size. These constrained-view checks do not claim an old OS. A separate iPad UI case exercises the actual system resize handle and documented full-screen restoration, preserving the selected pixel and testing palette return and picker cancellation in the smaller window. Column assertions wait for UIKit appearance/attachment and transition completion, compare visible safe-area content (the secondary background may extend beneath the sidebar), and distinguish collapsed/overlay navigation from two visible columns. Run results and inspected screenshots must qualify the exact commit before a release claim; the existence of this test matrix does not imply that every candidate passed.

Only two bounded synthetic screenshots are exported after XCTest completes, with no artifact uploads. Existing Library/store screenshot assets remain historical baseline images until the native iPhone/iPad/Mac surfaces are qualified together. This branch does not enable multiple app scenes, signing, entitlements or Store publication.

The regular-width system Photos popover dismisses by tapping outside it; its Close controls can refer only to the privacy-information banner. The iPad tests inspect the actual whole Photos popover bounds, dismiss outside that region, and require the picker to disappear with the prior color/history/live state intact. Cancellation readiness does not depend on the remote photo grid finishing loading. Independent UI cases terminate their app process; saved-color preview Close is exercised through three consecutive cycles. Compact sheet Cancel remains covered.

Official `performAccessibilityAuditWithAuditTypes:issueHandler:error:` checks run in separate bounded stages on every device in the primary matrix. Empty palette, saved palette, sampled photo, unavailable live camera and offline policy error each use all SDK-supported audit types. The issue handler logs the exact audit type, descriptions and element and returns NO; no blanket ignores hide hit-region, clipping, contrast or description problems. Numerical RGB/hex labels are asserted independently of swatch color. Audit results, native resizing and the full expanded device matrix remain unqualified until the exact candidate succeeds; adding these tests is not itself proof of support.
